## 1. 專案概述

### 1.1 背景

家庭共同管理收支常見痛點:

- **共同預算難以掌控**:現金、信用卡、電子支付分散,月底對帳耗時。
- **訂閱服務氾濫**:Netflix、Spotify、YouTube Premium 等月費容易忽略。
- **兒童零用錢缺乏引導**:父母難以系統性教導儲蓄與消費。
- **缺乏視覺化**:僅靠 Excel 或紙本,無法即時看出哪類超支。
- **資料隱私**:坊間記帳 App 將家庭財務上傳第三方,隱私風險高。
- **真實生活多例外**:買了個特殊東西、付了個沒列過的費用,系統不該擋住使用者。
- **多家庭管理**:一個系統管理員可能負責多個家庭(自己家、父母家、兄弟姊妹家),資料需要分離。

### 1.2 目標

建立一套 **本地優先、可離線使用、家庭成員共編、權限分級、例外友善、支援多家庭** 的記帳系統,協助家庭:

1. 即時掌握預算執行情況
2. 自動化追蹤訂閱與週期性支出
3. 培養兒童金錢觀(零用錢、儲蓄目標、消費限制)
4. 一鍵匯出做為報帳 / 報稅 / 年度檢視
5. **遇到沒預設的選項時,使用者仍能 5 秒內完成記錄**
6. **多家庭資料完全分離,系統管理員可彈性指派成員**

### 1.3 適用對象

| 對象 | 場景 |
|---|---|
| 一般家庭(2 大 1~3 小) | 月度家庭帳務、訂閱控管 |
| 單親家庭 | 個人 + 子女帳務 |
| 同住親友 | 共同生活費分攤 |
| **多家庭管理人** | 一位系統管理員管理自己家、父母家、兄弟姊妹家,各自獨立 |

### 1.4 設計原則(本版核心精神)

#### 原則一:**例外優先 (Exception-First)**

> **任何固定選項都不能成為阻擋記帳的牆。所有下拉、單選、預設清單的最後一項,必須永遠是「其他 / 自訂…」並可即時填寫。**

實作要點:

| 項目 | 規範 |
|---|---|
| 預設選項 | 提供常見值加速輸入 |
| 例外入口 | 永遠在清單最末,虛線分隔 |
| 輸入方式 | 選「其他」直接展開輸入框,不另開彈窗 |
| 記憶機制 | 自動記憶最近 5 筆自訂值,下次出現於「最近使用」 |
| 升格流程 | 父母可將自訂值「升格」為家庭共用選項 |
| 範圍 | 兒童自訂值僅自己可見;父母自訂值家庭共用;系統管理員全可見 |

#### 原則二:**金額池模型 (Amount Pool Model)**

`
┌──────────────────────────────────────────────┐
│  家庭月度總池 (Family Pool)                   │
│  = 父母設定的月度總預算                        │
└──────────────────────────────────────────────┘
              │                       │
              ▼                       ▼
   ┌─────────────────┐     ┌─────────────────────┐
   │ 父母池           │     │ 兒童池(每位兒童獨立)   │
   │ 額度 = 總池       │     │ 上限 = 家長自訂範圍    │
   │ 可動用 =          │     │ 受單筆/週/月多層限制    │
   │   總池 − Σ兒童池  │     │                     │
   └─────────────────┘     └─────────────────────┘
`

規則:

| 角色 | 可動用額度 | 上限設定者 |
|---|---|---|
| 父母 | 全池(可隨時調整總池) | 自己 |
| 兒童 | **家長設定的範圍**(被超限直接擋下,無審核流程) | 家長 |
| 儲蓄目標 | **獨立於消費池**(存入不佔消費池額度,提領回現金算支出) | — |

> **v0.3 修正**:兒童超過範圍時,系統直接以提示擋下,**不再觸發父母審核**。若需調整,父母下次手動放寬即可。

家長設定兒童範圍的方式(三軸,可同時啟用):

1. **單筆上限**(例:單次不可超過 NT\)
2. **週/月額度**(例:每週 NT\、每月 NT\,000)
3. **比例上限**(例:佔兒童零用錢的 N%)

#### 原則三:**RWD 必要 (Responsive-First)**

- 預設開發斷點:**桌面 ≥1024px / 平板 768–1023px / 手機 <768px**
- **手機優先設計**:80% 使用情境為手機,UI 元件以手機為基準再向上延伸。
- 表單欄位在小螢幕自動改為單欄堆疊。
- 圖表在小螢幕自動切換為摘要卡片 + 展開細節。
- 抽屜式選單取代固定側邊欄(< 768px)。
- 觸控目標 ≥ 44×44 px。
- 支援橫向與直向。

#### 原則四:**本地優先 / 自架 (Self-Hosted)**

- 部署於自有硬體(NAS、樹莓派、家用伺服器、租賃 VPS)。
- 資料不出自家網路(僅透過 HTTPS 對外)。
- 提供 Docker Compose 一鍵部署包(Laravel Sail 為基礎)。
- 提供還原映像檔腳本(資料 + 設定 + 附件打包)。

#### 原則五:**多家庭隔離 (Multi-Family Isolation)**

- 每筆資料都帶 amily_id,App 內任何查詢都會自動過濾。
- 系統管理員(system_admin)不受此限,可跨家庭查詢 / 編輯。
- 使用者可同時屬於多個家庭(罕見,主要為過渡期)。
- 家庭之間的附件、附件儲存路徑,皆以 amily_id 為前綴分離。

## 2. 角色與權限 (RBAC)

### 2.1 角色定義

| 角色 | 代號 | 範圍 | 說明 |
|---|---|---|---|
| 系統管理員 | system_admin | **跨家庭全域** | 管理多個家庭:新增 / 停用家庭、指派使用者到家庭、查看所有家庭 |
| 父母(管理者) | parent | 單一家庭 | 家庭帳務全權,可編輯家庭內任何成員資料、預算、訂閱、兒童範圍 |
| 兒童 | child | 單一家庭 | 可新增自己的支出/收入(受範圍限制)、查看自己的錢包與儲蓄目標 |
| 訪客 | guest | 單一家庭 | 僅可查看家庭公開報表 |

> **角色數量不設限** — 父母可多位、兒童可多位;首頁可依需求擴充自訂角色(例如「祖父母」、「保母」)。

### 2.2 多家庭關係示意圖

`
        ┌────────────────┐
        │ system_admin   │
        │ (王先生)        │
        └───────┬────────┘
                │ 管理多個家庭
       ┌────────┼────────┐
       ▼        ▼        ▼
   ┌──────┐ ┌──────┐ ┌──────┐
   │ A 家庭│ │ B 家庭│ │ C 家庭│
   │(自己) │ │(父母) │ │(兄弟) │
   └──┬───┘ └──┬───┘ └──┬───┘
      │        │        │
   parent    parent    parent
   child     child
`

- 王先生本身在 A 家庭是 parent,在 B、C 家庭只是被指派的成員(可為 parent 或 child)。
- A、B、C 三家庭的資料彼此隔離,王先生只能在「切換家庭」後看到該家庭內容。
- 只有 system_admin 角色可建立新家庭。

## 3. 功能需求

### 3.1 帳號與認證

- **登入 / 登出**:帳號密碼、Session(Sanctum)
- **註冊流程**:由第一位系統管理員(或第一位父母)建立,後續以邀請碼加入
- **密碼強度檢核** + 雜湊儲存(bcrypt / argon2)
- **雙因素驗證(2FA)** — TOTP(選用)
- **登入失敗鎖定**:5 次錯誤鎖 15 分鐘
- **會話逾時**:閒置 30 分鐘自動登出
- **忘記密碼**:Email 重設連結
- **個資加密**:身份證/生日等敏感欄位加密儲存

### 3.2 家庭預算 / 金額池管理

- **新增預算**:週期(預設月/季/年 / **自訂起訖日**)、總額、分類限額、可細項(早餐/午餐/晚餐)
- **自動扣減**:新增支出時依分類自動從對應預算扣減
- **預算複製**:可快速複製上月預算為本月
- **預算警示閾值**:預設 80% / 100%,**可自訂百分比**
- **預算使用率即時顯示**:首頁儀表板進度條
- **兒童範圍設定**:單筆上限 / 週上限 / 月上限 / 比例上限(任選,可疊加)
- **兒童範圍彈性**:父母可「臨時加碼」兒童額度,加碼可設到期日

### 3.3 記帳核心

#### 3.3.1 收入

- 欄位:金額、日期、來源(薪資/獎金/零用錢/紅包/退款/**其他 → 自填**)、帳戶(**其他 → 自填**)、備註、附件
- **自動收入範本**:每月固定入帳可設週期,自動產生

#### 3.3.2 支出

- 欄位:金額、日期(預設今天)、分類(主+子)、帳戶、付款人(成員/**其他 → 自填外人姓名**)、備註、附件、標籤
- **退費/作廢**:支援負數金額或獨立退費單
- **編輯歷史**:保留修改前快照
- **超兒童範圍時**:系統直接擋下 + 友善提示「超過家長設定 NT\」,**不觸發審核**(v0.3 新規範)

#### 3.3.3 轉帳

- 帳戶之間資金移動(現金 → 信用卡繳款)
- 自動產生兩筆對沖紀錄,避免重複計算收支

#### 3.3.4 分帳/拆帳

- 一筆消費由多人分攤(例如:家庭出遊)
- **分攤方式**:平均 / 自訂比例 / 自訂金額 / 按人數
- **未涵蓋的人員**可手動補入

### 3.4 分類管理

- **兩層分類**:主分類 → 子分類
- 預設內建(餐飲、交通、居家、醫療、教育、娛樂、其他)
- **每層皆提供「其他 → 自訂」入口**
- **自訂值可一鍵升格為家庭共用選項**
- 分類圖示與顏色(用於圖表)
- 分類排序
- **分類停用**:停用後既有的交易仍可顯示,但無法選為新紀錄

### 3.5 訂閱管理

- 欄位:服務名稱、費用、週期(月/年/週/**自訂週期(天數/特定日期)**)、計費日、付款帳戶、分類、備註、連結
- **下次扣款日自動計算**
- **即將到期通知**:前 3 天提醒(可自訂天數)
- **免費試用期**:試用到期提醒
- **共用成員**:標註家庭共享,避免重複計算
- **統計**:月/年訂閱總支出
- **跳過一期**:產生停繳紀錄但不刪訂閱

### 3.6 週期性消費(非訂閱)

- 水電瓦斯、房租、管理費、學費等
- 同訂閱機制,但分類為「週期性帳單」
- 一樣支援自訂週期

### 3.7 查詢 / 篩選

- 多條件篩選:日期區間、分類、成員、帳戶、金額範圍、標籤、關鍵字
- **儲存常用篩選條件**
- 列表 / 月曆視圖切換
- 排序:日期/金額/分類
- **自訂欄位顯示**:使用者可決定列表要顯示哪些欄位

### 3.8 新增方式

#### 3.8.1 快速新增(手機優先,RWD 優化)

- 一頁完成:金額 + 分類(主,可跳到子) + 備註(選填)
- 自動帶入:今天日期、上次使用帳戶、上次付款人、上次使用的自訂值
- **分類選擇器永遠把「其他 → 自填」放最後**
- 支援語音輸入金額(選用)
- **若選「其他」展開輸入框,送出按鈕不變位置,避免誤觸**

#### 3.8.2 完整新增

- 展開所有欄位:金額、日期、分類、子分類、帳戶、付款人、標籤、附件、分帳、備註
- 每個欄位皆有自訂入口
- 適用於電腦或複雜記錄

### 3.9 匯出功能

- **格式**:CSV、XLSX、PDF
- **範圍**:全部 / 月份 / 自訂區間 / 自訂篩選
- **PDF 月報範本**:含封面、收支總覽、分類圓餅圖、月度趨勢圖
- **Email 定期寄送**:每週/月自動寄送報表 PDF

### 3.10 報表與分析

- **儀表板**(首頁):
  - 本月收入 / 支出 / 結餘
  - 各分類圓餅圖
  - 近 6 個月趨勢折線圖
  - 訂閱總額提醒
  - 預算使用率條
  - 兒童錢包摘要(child 角色看到自己的版本)
- **成員消費排行**
- **同比/環比**:與上月、去年同期比較
- **儲蓄達成率**
- **圖表自訂區間**:可選 7 天/30 天/季/年/**自訂日期**
- **單一幣別 TWD**:報表不需貨幣換算,簡化邏輯

### 3.11 通知與提醒(Email + Discord Webhook)

通知管道:**Email (SMTP) 為主 + Discord Webhook 為輔**,兩者皆為免費 API。

支援的通知類型:

| 類型 | Email | Discord |
|---|:-:|:-:|
| 預算超支警示(80% / 100% / 自訂) | ✅ | ✅ |
| 訂閱即將扣款(前 3 天 / 自訂) | ✅ | ✅ |
| 兒童消費超限通知(僅父母) | ✅ | ✅ |
| 兒童儲蓄目標達標 | ✅ | ✅ |
| 月報 / 週報自動寄送 | ✅ | ✅ |
| 家庭邀請 | ✅ | ❌(僅 Email) |
| 系統公告 | ✅ | ✅ |

### 3.12 兒童專屬功能

### 3.18 例外/自訂設計模式(橫切關注點)

### 6.3 開發環境(XAMPP)

**XAMPP 是什麼?**
- 一套本機開發環境,內含 Apache(MariaDB + PHP + Perl)
- 您已安裝,代表 Apache + MariaDB + PHP 已經可用

**Laravel 如何在 XAMPP 上運作?**

方式 A — 用 Laravel 內建伺服器(推薦開發期)
```bash
cd C:\xampp\htdocs\family-accounting
php artisan serve
# 瀏覽器打開 http://localhost:8000
```

方式 B — 用 XAMPP 內建 Apache(部署或長期開發)
```
1. 在 C:\xampp\htdocs\ 建立專案資料夾
2. 修改 C:\xampp\apache\conf\extra\httpd-vhosts.conf 加入 vhost
3. 瀏覽器打開 http://family-accounting.local
```

**MariaDB 連線設定(.env)**
```ini
DB_CONNECTION=mariadb
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=family_accounting
DB_USERNAME=root
DB_PASSWORD=             # XAMPP 預設空密碼
```

**為什麼選 MariaDB?**
- 您已在用,XAMPP 內建,零設定
- 與 MySQL 完全相容,Eloquent 不用改
- JSON 欄位支援略遜 PostgreSQL 但對本系統夠用

**正式部署(自架)** 
- 同樣可沿用 LAMP 架構(Linux + Apache + MariaDB + PHP),把本機搬到 VPS
- 或用 Laravel 支援的其他 Web Server(Nginx + PHP-FPM)
- 之後若團隊變大再考慮 Docker;**v0.4 不引入 Docker 避免增加學習成本**

## 附錄 A:ORM / Eloquent 速成指南

### A.1 ORM 是什麼?

ORM = Object-Relational Mapping,用「物件」代替「SQL」操作資料庫。

| 沒用 ORM | 用 ORM (Eloquent) |
|---|---|
| INSERT INTO users (name) VALUES ('王') | $user = new User(); ->name = '王'; ->save(); |
| SELECT * FROM users WHERE id = 5 | $user = User::find(5); |
| SELECT * FROM users WHERE family_id = 5 | $users = User::where('family_id', 5)->get(); |
| DELETE FROM users WHERE id = 5 | User::find(5)->delete(); |

### A.2 Laravel 裡一張表 = 一個 Model

`
app/Models/
├── User.php             ← 對應 users 表
├── Family.php           ← 對應 families 表
├── Transaction.php      ← 對應 transactions 表
├── Account.php          ← 對應 accounts 表
├── Category.php         ← 對應 categories 表
└── ...
`

### A.3 Eloquent 對 SQL 知識的對應

| SQL | Eloquent |
|---|---|
| SELECT | Model::all() / ->get() |
| WHERE | ->where('欄位', '值') |
| WHERE ... AND ... | ->where(...)->where(...) |
| WHERE ... OR ... | ->orWhere(...) |
| ORDER BY | ->orderBy('欄位') |
| LIMIT 10 | ->take(10) |
| COUNT(*) | ->count() |
| JOIN | ->join(...) 或關聯 ->with(...) |
| GROUP BY | ->groupBy(...) |
| 找單筆 | ->first() / ->find() |

### A.4 關聯(取代 JOIN)

`php
// 一個家庭有多個成員
class Family extends Model {
    public function members() {
        return ->hasMany(User::class);
    }
}

// 一個使用者有多筆交易
class User extends Model {
    public function transactions() {
        return ->hasMany(Transaction::class);
    }
}

// 一筆交易屬於一個分類
class Transaction extends Model {
    public function category() {
        return ->belongsTo(Category::class);
    }
}
`

使用:

`php
 = Family::find(5);
echo ->name;                                    // 家庭名
foreach (->members as ) { ... }            // 該家庭所有成員
foreach (->transactions as ) { ... }      // 該使用者所有交易
echo ->category->name;                         // 交易分類名
`

### A.5 什麼時候還是寫 SQL?

Eloquent 處理 90% 沒問題。剩下 10%:

- 複雜報表統計 → 用 DB::select('SELECT ...') 寫原生 SQL
- 效能極致優化 → 寫原生 SQL

`php
// 範例:本月各分類總支出
 = DB::select("
    SELECT c.name, SUM(t.amount) as total
    FROM transactions t
    JOIN categories c ON t.category_id = c.id
    WHERE t.family_id = ? AND t.type = 'expense'
      AND t.occurred_at BETWEEN ? AND ?
    GROUP BY c.id
    ORDER BY total DESC
", [, , ]);
`

> **結論:您學 Laravel 不會浪費 SQL 知識,兩者並存,隨時切換。**
